**空间布局工具：面向锦奕业务的商业化改造计划**

更新日期：2026-11-06。用途：作为后续 `/goal` 的实施与验收依据。初版只分析和编写计划；2026-11-05 已按后续任务完成 G1/G2/G3 的本地实现与阶段验收；未连接业务数据库或操作线上环境。

**1. 判断依据与产品方向**

本计划核对了 `D:/work/canteen-layout` 的 PRD、README 和编辑器源码，以及 `D:/work/zhaoshang` 的 AGENTS、README、当前业务选项、房源/咨询/媒体集合、员工权限、网站入口和近期上线记录。线上可用性未在本轮重新验证；以下客户流程属于根据业务代码提出的产品建议，需要在试点中验证。

招商系统当前代码的场景是学校、工业园区、写字楼；旧文档中社区、文旅、购物中心等描述不能直接作为此次范围。还应区分独立静态公司官网 `website/` 与 Next/Payload 的房源及需求入口，不能把它们当成同一个网站发布链路。

建议定位：**服务招商顾问与餐饮客户的空间方案工作台**。顾问录入场地和需求，制作、比较方案，向客户展示，收集修改意见，并关联原来的房源或咨询。第一版完整编辑优先服务电脑端顾问；客户先获得手机可看的方案与反馈入口，再逐步获得受限自助编辑能力。

目标流程：

> 关联房源/咨询或新建独立方案 → 记录客户需求 → 导入及校准场地资料 → 圈定本次布置范围 → 摆放和检查 → 保存 A/B 方案 → 导出或分享明确版本 → 收集意见 → 修改并重新交付。

首版业务场景聚焦三类：小型食堂档口的新铺布置；整层饭堂中的局部改造；园区/写字楼员工餐饮空间的桌椅与设备调整。用这三类场景检验功能，不继续无边界扩大品类。

**2. 当前差距：为什么功能增加了，仍然像原型**

| 缺口 | 源码或业务依据 | 对客户的实际影响 |
| --- | --- | --- |
| 项目缺少完整身份和资料 | `src/model.ts` 的 Project 目前只有名称、范围尺寸、轮廓与物体 | 无法明确是谁的方案、针对哪个铺位、哪一版、由谁修改 |
| 数据保存脆弱 | `src/App.tsx` 手动覆盖单个 `canteen-layout-project` localStorage 键 | 切换客户、浏览器清理或忘记保存会造成方案丢失/混淆；JSON 是备份手段，不能承担日常项目管理 |
| 编辑状态分散 | App 的 `multi`、store 的 `selected`、PlanEditor 的工具/轮廓模式、Scene3D 的移动状态分别维护 | 模式、快捷键、选择和撤销容易互相干扰，继续叠加功能会增加回归风险 |
| 场地与本次工作范围合一 | 只有一个 `outline`；区域仍是普通矩形 Item | 圈出局部区域会改变整个地面，不能完整表达“整层饭堂保留背景，只改其中一块” |
| 无可靠的实地资料入口 | 未提供底图校准、固定柱体、工程点位和测量工具 | 用户面对现场照片/平面图，仍需凭感觉重新画；很难建立尺寸信任 |
| 操作缺少专业效率工具 | 当前以 100mm 网格吸附、属性数字、单件拖动为主 | 无法方便地贴墙、控制通道、重复摆桌椅、定位遮挡物体 |
| 设备库有数量，缺少规格体系 | 62 个预设；模型主要按外包尺寸整体缩放；自定义物件使用 prompt | 桌腿、把手等会随尺寸一起拉伸；设备是否可改规格、桌面设备离地多高不明确 |
| 没有可交付的方案包 | 当前主要是 PNG 与 JSON | 客户看不到明确尺寸、设备数量、方案版本、修改说明和重点视角 |
| 客户访问链路缺失 | 当前为本地单页；没有方案云端归属、只读分享和反馈契约 | 不能自然接入顾问的多客户服务，也无法控制客户访问范围 |
| 稳定性尚未形成产品标准 | 全项目快照历史；App 整体订阅 store；3D 活跃时持续渲染；模型单独创建 | 大场景的性能、保存恢复、异常降级还需实测；不能仅凭 build 成功宣称商用 |

保留现有价值：毫米单位、共享空间数据、SVG 编辑器、React/TypeScript/Zustand、R3F/Three.js、墙窗关联与不规则轮廓都可以继续使用。当前没有足够证据支持推倒重写或切换画布引擎。

**3. 首版范围与成功标准**

首版至少应让顾问完成三个不同客户方案的创建、保存、恢复与交付；能根据有已知尺寸的场地图制作布局；能保留整场地背景并编辑局部；能产出包含平面、关键尺寸、设备清单和三维视图的成果；客户能在手机上看指定版本并反馈。

界面不是最后才处理的装饰工作。G2 就要建立可读、可操作的专业工作台，并在后续各阶段沿用：正常字号、清晰的选中态、可理解的操作模式、持续可见的保存状态、可恢复的错误反馈。效果验收以实际视口和完整任务为准。

首版暂不承诺：施工级 CAD/BIM、消防/卫生合规自动判定、完整机电设计、照片级渲染、自动生成布局、在线交易支付、完整 CRM、多租户计费、多人实时协同、手机端完整绘图。方案建议与现场待核实条件应明确区分。涉及通道提示时使用可配置的业务参考值，不把某个固定数字写成合规结论。

**4. 实施顺序与里程碑**

| 阶段 | 核心目标 | 依赖 | 阶段成果 |

| G6 | 版本比较与客户交付 | G5 | 可以内部试用、向客户交付的方案包 |

**G1：多项目与数据安全**

目标：先保证任何后续编辑都能被可靠保存，并能区分客户及方案。

- 增加简洁项目列表：新建、打开、重命名、复制、删除及恢复。保留明确“打开示例”入口，真实新项目不默认塞入一套虚构饭堂。
- 建立项目 ID、文件格式版本、创建/修改时间、客户或场地称呼、用途、简单需求备注；关联房源/咨询 ID 暂可为空。
- IndexedDB 保存项目与后续图片资产；保存界面区分“未保存、保存中、已保存、失败”。每个完成的编辑动作触发合并保存，拖动中不逐帧写盘。
- 增加本地恢复副本；写入失败保留工作内存及上一份成功记录，可重试/导出。多标签页检测版本冲突，避免无提示互相覆盖。
- 明确区分工作草稿、用户命名的方案副本和恢复记录。先用完整快照，不引入事件溯源或通用协同框架。
- 将当前 localStorage 方案一次性转入新项目库并核对成功后再处理旧记录；当前 JSON 可导入，未知未来版本明确拒绝或只读，不做无限历史兼容。

涉及：`src/model.ts`、`src/store.ts`、`src/projectIO.ts`、`src/App.tsx`；新增聚焦的本地存储与项目列表模块。

验收：创建三个项目并来回切换，副本修改不影响原件；输入/拖动后刷新能恢复；写入失败不会显示成功；删除可恢复；两个标签页修改同一项目不会静默覆盖；现有矩形和不规则 JSON 能导入且保持尺寸。针对存储失败、导入和恢复做必要回归。

**G2：编辑状态与工作台体验**

目标：让用户知道现在在编辑什么、哪个工具在生效、如何取消与恢复。

- 顶部保留项目、保存状态、撤销/重做、导出与视图；左侧切换设备库/对象列表；右侧按场地、单选、多选展示对应属性。
- 明确区分场地轮廓编辑、建筑构件编辑、设备布置和三维查看。画墙、画区域等临时工具有完成/取消提示。
- 将选择集合、主选对象、当前工具集中管理；2D、3D、对象列表共用选择。修复 Esc、Delete、输入框和指针捕获之间的冲突。
- 多选时提供真正批量可编辑的公共属性；不再把多个对象选择伪装成单个对象属性编辑。
- 增加对象搜索、显隐、锁定、定位；这些能力优先帮助选中薄墙、重叠设备和被遮挡的门窗。
- 用侧栏/对话框替换 prompt；整理字号、间距、颜色、图标与按钮命名。主要表单文字以 13–14px 左右为起点，少量辅助文字可更小，在真实分屏下验收。
- 记住分屏比例、面板开关与常用视图。三维提供俯视、斜视、复位和清晰的移动开关；编辑时选中态应落在物体本身。
- 适度拆分 App 与编辑器交互代码，按实际职责组织；避免创建通用插件系统、复杂命令总线或为了换 UI 引入另一套画布。

验收：1366×768 与 1920×1080 下完成“选择→多选→修改→拖动→取消→撤销→分屏切换”；关键按钮不被遮挡，输入不会触发对象删除，工具退出后不残留拖动，重叠对象可从列表选中。提交前后截图及实际操作记录。

**G3：现场底图、整场地与本次规划范围**

目标：真正表达整层饭堂内的局部改造，而不是不断替换唯一地面。

- 第一小步支持 PNG/JPEG 底图：导入、旋转、透明度、显隐、锁定；点选两点输入已知距离完成毫米尺度校准。先不做 CAD/DWG 解析和自动识图。
- 图片存入项目资产，方案引用资产 ID。普通 JSON 明确不含哪些外部资产；提供包含底图的可移植项目包，禁止只保存会失效的临时 blob URL。
- 区分整场地轮廓、规划区域、功能分区和固定障碍物。保留场地原点与世界坐标；切换规划区域不挪动现有设备。
- 支持一个项目内的多个命名规划区域，当前激活区域有明确高亮；区外背景和固定设施可锁定、弱化显示。
- 功能分区支持凹多边形、名称和面积；定义重叠区的统计方式，不能重复相加后仍称其为场地总面积。
- 补充矩形柱体/固定设施、入口和排烟/上下水/电力等点位标记，允许“待核实”备注。此处只表示位置与已知条件，不模拟工程系统。
- 支持基础测距和长度标注，墙端点吸附、转角连接视觉修整；从测量资料到轮廓的步骤可回退。
- 先做好单层、简单凹形场地和障碍物。多楼层、任意洞口布尔运算、不相连场地等在实际案例证明需要后单列目标。

验收：导入含一段已知 5000mm 长度的底图并校准；描出 L 形场地，圈定局部经营区，放置柱体和门窗；区外家具保留且按锁定规则不可误移；2D/3D 的位置、范围和面积一致；重开项目和跨浏览器导入项目包后底图仍可用。

**G4：布局效率、标注与空间检查**

目标：减少逐件摆放与反复输入数字，让顾问能解释布局是否合理。

- 在网格吸附之外增加墙边、物体边缘/中心、端点吸附与参考线；明确开关，Alt 临时禁用。
- 增加直接旋转、方向键微移、复制后继续放置、桌椅组合与按行列重复摆放。组合保持成员 ID，能够解组和单独调整。
- 对齐/分布按实际旋转后的边界计算，并尊重锁定、墙窗从属和活动规划区域。
- 提供对象间净距、墙边净距和关键尺寸标注。量取几何边界，不能用两个对象中心距离冒充通道宽度。
- 检查完整旋转轮廓与规划边界/障碍物的关系。越界、明显碰撞、参考净距不足给出可定位提示；不要只检查中心点，也不要默认强制禁止所有重叠。
- 默认忽略区域覆盖与桌面设备合理叠放；区分固定障碍碰撞、门扇开启范围与一般软提醒。暂不实现全自动动线优化。
- 建立透明的座位统计规则：以明确声明的座椅/组合座位数统计，组合展开后不重复计数，禁止靠中文名称猜容量。

验收：从一个四人桌椅组合快速布置 6 组；批量旋转/复制/撤销后相对位置不变；斜墙和旋转设备可正确吸附、量距；设备中心在区域内但一角越界时能提示；桌上的小设备不被默认误判成不可接受的碰撞。

**G5：设备规格与三维质量**

目标：现有库先变得可信、易找、比例稳定，再扩大素材数量。

- 为现有条目建立稳定 catalog ID、类别、型号/规格、尺寸编辑规则、座位数/数量单位、资产来源和备注；明确区分通用示意设备与实际已核实产品。
- 自定义设备支持新增、编辑、删除、复用及预览，能够从已有条目另存；维护规格变更对场景实例的影响规则，不能无提示改动已有方案。
- 增加普通设备离地高度，支持吧台上的咖啡机、饮料机及台上置物架；明确与门窗窗台高度的不同语义。
- 先重做最常用的 10–15 个模型。参数化模型保持桌腿粗细、门框、把手等关键部件的合理尺寸；区分可伸缩主体与固定细节，避免整体拉伸。
- 对少数客户展示价值高的设备评估合法来源的 GLB；统一坐标、原点、毫米比例、材质、包围盒和缩略图。外部资源不可用时保持可辨认的回退模型。
- 固定目录的缩略图可在构建前生成并缓存；自定义规格才按需渲染。大批重复模型先测量，再做必要的几何/材质共享和实例化。
- 提供简洁场景光照、地板/墙面有限材质选项、墙体显隐/半透明与选中轮廓。优先保证空间关系清楚，避免把预算耗在无用途的装饰素材上。

验收：10–15 个主要模型提供固定视角前后对比；修改尺寸后细部不出现明显拉伸；桌面设备正确离地，导入/导出后不丢失；缩略图与场景使用同一规格；不存在虚构厂家/价格/模型授权。资产缺失时仍可编辑与导出。

**G6：A/B 方案和客户交付成果**

目标：顾问能把方案交给客户讨论，而不只是展示编辑器截图。

- 用完整方案快照实现 A/B 副本与明确命名的交付版本；比较面积、设备数量、座位数和备注。先不做复杂对象级差异合并。
- 导出有标题、版本、日期、尺寸标注、分区图例和说明的 2D 平面；增加稳定的 3D 截图与保存视角。
- 自动生成设备清单：类别、名称、规格、数量、分区，支持 CSV；设备与清单一一对应。新增/替换/利旧信息按明确字段统计。
- 增加可打印方案页，组合平面、三维视图、清单及“已确认/待核实”资料；支持浏览器打印为 PDF。确需一键下载 PDF 时再引入适合的库。
- 报价暂作为手工填入的可选估算项，未知不填 0，不根据模型名称编价格。不把估算当作最终合同或自动算出的建设成本。
- 提供客户展示模式，隐藏编辑器控件、内部备注和未确认的内部资料；输出内容以选定交付版本为准。

验收：同一个场地做 A/B 两版，修改 B 不影响 A；导出平面、3D 图、CSV 和打印方案包，标题/版本/数量一致；换电脑导入项目包后可复现主要成果；未包含的资产和暂不支持的导出项有明确说明。

本阶段才涉及两个仓库。执行时重新读取 `D:/work/zhaoshang/AGENTS.md` 和最新代码；本规划不是连接生产库或自行部署的授权。
