## 性能实测

Windows 11 / AMD Ryzen 7 H 255 / Radeon 780M / 系统报告总内存 23GB，Chrome 156.0.8078.80，1440×900、DPR 1、Vite 开发模式、独立无头浏览器。合成场景混合餐桌、椅子、工作台、冰箱，真实连续鼠标移动；每组 30 次项目状态更新。

| 对象数 | 视图 | 帧间隔中位数 | 帧间隔 P95 | 指针到状态更新 P95 |
| --- | --- | --- | --- | --- |
| 100 | 二维 | 16.7ms | 50.0ms | 0.9ms |
| 100 | 分屏 | 16.7ms | 49.9ms | 0.8ms |
| 300 | 二维 | 16.7ms | 83.3ms | 1.2ms |
| 300 | 分屏 | 16.7ms | 100.0ms | 1.2ms |

首次排查的 300 件分屏渲染基线中位数为 100.1ms、P95 433.4ms。该轮合成数据直接注入 store、未同步项目库修订，触发保存冲突，仅用于定位渲染成本。最终测量改为从正常项目库创建场景，并验证编辑后已保存；两轮存储条件不同，不作为严格 A/B 基准。实例化与减少重绘后的最终结果见上表。帧间隔包含浏览器调度、真实输入及绘制，不等同于纯 GPU 用时；状态更新耗时不等同于完成绘制耗时。仍有慢帧，300 件分屏本次最大间隔 116.7ms，不能据此承诺任意电脑、任意复杂模型均为 60fps，也没有将此视为 G8 的办公机/真实操作者验收。

原始记录：[优化前](prd-evidence/performance-before.json)、[优化后](prd-evidence/performance.json)。仅相同规格的重复模型合批；大量不同规格或透明复杂模型仍可能较慢。

## 数据与操作规则

- 文件格式升级为 2，保护新增标注和区域归属不被旧应用静默丢弃。版本 1 和未标版本文件在读取时升级，未知未来版本拒绝；不改写旧文件原件。
- 自定义库条目有独立 ID，复制产生新 ID；库修改/删除只影响后续添加，已摆放实例保留。个人库仍在当前浏览器，项目 JSON 携带场景实例而非整个个人库。
- 区域归属由用户明确分配，不根据名称猜测。分割第一段保留原 ID，第二段生成新 ID；原归属物件按中心落点重新归属，坐标不变。删除区域解除归属，撤销同时恢复。
- 区域面积为整场地内部分；重叠分区分别统计，不相加作为场地总面积。物件“外包占地”指长×宽的规格矩形。
- 尺寸标注是绘制时的独立几何记录，不是关联约束；后续移动家具不会自动改标注。楼梯为单层场景中的示意构件，不创建二层楼板。
- 客户成果生成时以模态窗口暂时阻止编辑，确保图片和清单同一时点；文件固定为生成时快照。内部需求备注不输出，隐藏对象不出现在图片或清单。
- 三维导出保持观察朝向，自动框住当前可见场景，去掉选中框；导出后恢复相机和画布。没有启用常驻 `preserveDrawingBuffer`。

## 复现与运行

```text
pnpm install
pnpm dev
pnpm build
pnpm preview
node tests/prd-workflow.cjs <已有 Playwright 包路径>
node tests/prd-performance.cjs <已有 Playwright 包路径>
node tests/g2-workbench.cjs <已有 Playwright 包路径>
```

运行需求为 Node ≥22.12、pnpm 11.5.0；产物 `dist/` 可放入静态 HTTP 主机。没有后端、账户服务或新增测试依赖。本机验收复用已有 Playwright 包和 Chrome；脚本分别使用 5187、5188、5186 端口、隔离数据，结束后关闭自己启动的服务及浏览器。性能测量应单独运行，避免其他负载干扰。
