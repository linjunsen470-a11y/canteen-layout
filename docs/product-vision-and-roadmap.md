# 产品定位、架构原则与后续演进路线图

> 本文档用于统一 `canteen-layout` 的产品定位、核心边界与工程决策，避免不同迭代在“工程精准度”与“老板低门槛上手”之间反复摇摆。后续任何功能重构或 PR 审阅都应优先遵循本文档的五大原则。

---

## 1. 目标用户与核心场景

**核心用户**：第一次开店的餐饮老板（或选址合伙人），站在刚租下或正在考察的毛坯铺位里。

**典型痛点**：
1. **铺位尺寸千差万别**：老板手里的铺位可能是 `6.2m × 5.4m` 社区小店、`12.5m × 7.6m` 临街宽铺，也可能是带柱子或直角凹位的 L 形铺。**固定尺寸的预设模板一旦换了尺寸就完全不适用**。
2. **先需要“概念估算”，再进入“精细微调”**：在动手逐件拖拽每一张桌椅之前，老板最急着弄清的是一组决策数字——**按我这个铺位的真实尺寸，后厨大概该划多大面积？前厅留多少面积？不同摆法大约能摆几桌、坐多少人？过道宽不宽、电力够不够、预算大概多少？**
3. **既要能算得准，又要能发给合伙人看懂**：平面图必须忠实于实测尺寸、门窗位置与柱子约束；3D 视图和导出的《合伙人方案书》必须有审美、能直接用于和合伙人拍板及给装修队复尺。

---

## 2. 五大产品与工程红线（Anti-Drift 原则）

### 原则一：实测铺位壳体神圣不可侵犯（保底真实性）
- 用户通过「按内墙净尺寸」「按外轮廓尺寸」或「从户型图描绘」建立的**外墙、门窗、承重柱、排烟/给排水点位和 `project.survey` 现场记录**是不可破坏的事实底座。
- 任何智能估算、智能分区或对比功能**绝对禁止**静默缩放、截断、重画或覆盖用户的外墙轮廓和实测门窗。

### 原则二：用“任意直角铺位上的参数化分区与排座估算”替代僵化预设
- 固定示范模板（`shopTemplates.ts`）只作为**灵感参考与案例浏览**，绝不是规划真实铺位的主路径。
- 针对任意尺寸的直角铺位（矩形、L 形、多凹位直角多边形），系统必须提供**贴合当前真实壳体的智能概念估算与半自动排布**：
  - 支持老板选择业态倾向（明档快餐/面馆、咖啡茶饮、精致中餐、企业食堂）、后厨方位（后置 / 左侧 / 右侧 / 不设后厨）、后厨面积占比（如 20%–50% 滑动调节）、桌型偏好与最小过道净距（800 / 950 / 1100 mm）；
  - 基于当前铺位的真实室内净多边形做**精确正交多边形切分**，实时算出后厨面积、前厅就餐面积、餐厨比，并在避开真实门扇开启范围、承重柱和已有外墙的前提下，智能试排桌椅与核心厨具；
  - 把“后厨多大、前厅多大、约摆几桌/多少座、人均面积、预估电功率与预算”直接呈现在图面与预览面板上，让老板 10 秒建立全局概念。

### 原则三：非破坏性预览 → 显式单步可撤销落位 → 同壳 A/B 对比
- 智能估算与参数调节在预览层完成，**不直接污染当前项目**。
- 老板满意后有两个清晰去向：
  1. **应用到当前铺位**：仅更新内部功能分区与可替换的室内家具/厨具，保留全部实测外墙、门窗、柱子与底图，并作为**一条可 `Ctrl+Z` 整体撤销的历史记录**提交；
  2. **另存为对比方案**：基于同一套实测壳体另存独立副本，支持与当前方案**并排对比平面图与关键经营指标**（座位数、餐厨比、过道净距、电力、预算）。

### 原则四：如实报告几何事实，不伪造“通过”
- 空间冲突检查（`spaceChecks.ts`）与通道净距（含椅背占地）必须基于真实旋转多边形几何计算；
- 内墙实测基准（`interiorSurvey.ts`）与结构校验（`structure.ts`）必须口径一致（特别是内凹转角处的门窗边界，不能出现“实测合法却无法保存”的规则冲突）。

### 原则五：像 Figma 一样顺手，而不是像传统 CAD 一样晦涩
- 保持“画布优先、按需展开”的工作台结构，不阻断首次使用，但提供清晰的低门槛入口（新建实测铺位、智能分区估算、逛逛示范案例、一键切换装修风格、一键发给合伙人）。
- 实测录入要照顾非专业用户：支持清晰的米/毫米换算提示、一键自动闭合最后 1–2 段直角墙、整组四向防碰撞复制。

## 3. GitHub 开源标杆调研与设计理念借鉴

我们调研并核实了 GitHub 上 7 个同领域高星/代表性开源项目，提炼出最适合 `canteen-layout`（React + SVG 2D + Three.js 3D + Zustand）直接落地的设计模式：

| 开源项目 | 技术栈 | 核心可借鉴设计理念 | 在本项目中的落地方式 |
| --- | --- | --- | --- |
| [**pascalorg/editor**](https://github.com/pascalorg/editor) (~25.7k★) | React + R3F + Three.js + Zustand | **非破坏性 2D 预览层**（修改提交前先在独立层预览）；基于距离场的通道/门扇/碰撞可达性检查；截图模式自动隐藏辅助浮层 | 智能分区估算弹窗内实时非破坏性 SVG 预览；`takingGallery` 干净截图模式；基于真实椅背净距的通道提示 |
| [**wy51ai/floorplan-3d**](https://github.com/wy51ai/floorplan-3d) (~3.9k★) | SVG 2D + Three.js | **2D/3D 双向联动 + 半墙剖视 + 分区飞入聚焦**；贴墙磁吸摆放；按分区材质自动汇总面积与造价 | 保留半墙剖视与多视角切换；实时按分区汇总后厨/前厅面积、造价与配电估算 |
| [**furnishup/blueprint3d**](https://github.com/furnishup/blueprint3d) (~2.0k★) | TypeScript + 2D + Three.js | **物件物理依附分类**（`WallFloorItem` 靠墙炉灶/卡座、`InWallItem` 门窗/出餐窗、`FloorItem` 独立散台）；面向相机的外墙自动隐藏 | 智能排布引擎严格区分靠墙卡座/热厨贴边与中央岛台/散台；后续在 3D 狭窄铺位视角增强外墙遮挡优化 |

| [**laanlabs/openPlan3D**](https://github.com/laanlabs/openPlan3D) (~335★) | TypeScript + Three.js | **非破坏性墙体透视 X-Ray**；多选对齐与均匀分布；带图签（店名/比例尺/面积/座数）的打印级导出 | 导出 2D PNG 与《合伙人方案书》带完整图签信息；强化整组四向等距复制 |

## 4. 分阶段实施路线图

### 第一阶段（当前分支落地）：实测底座修复 + 任意直角铺位智能分区估算
1. **修复 PR #4 内凹转角门窗校验 bug**：让 `openingError` 对 `surveyWall` 放行合法的内墙净角范围（不再因墙中心线比内墙面短半墙厚而误报错），并补充 L 形内凹角回归测试。
2. **新增「智能分区与摆桌估算」引擎与交互工作台**（`src/conceptPlanner.ts` + `src/ConceptPlannerDialog.tsx` + `src/PlanMiniPreview.tsx`）：
   - 适配任意尺寸的直角矩形与 L 形/多凹位实测铺位；
   - 精确正交多边形切分后厨区/前厅区，实时可视化展示面积、占比、桌型分布、座位数、预估电力与预算；
   - 严格避开真实外墙、已有门扇开启范围、承重柱与固定设施，支持一键应用（可撤销）、同屏 A/B 对比（当前方案 vs 估算方案）或另存为对比方案。
3. **补齐老板高频易用性短板**：
   - 逐段录入增加 **「一键自动闭合」** 与米/毫米直观换算提示；
   - 新建弹窗恢复清爽的 **「示范案例参考」** 入口（盘活 4 套内置精品模板）；
   - 整组属性补齐 **左/右/上/下四向防碰撞相邻复制**；
   - 场地设置增加 **一键装修氛围主题包**（原木暖调 / 奶油咖啡 / 暖调小馆 / 明亮快餐 / 素水泥毛坯）；
   - 导出 2D PNG 在无显式入口点位但有外墙门时自动补全主入口方向提示。

### 第二阶段：深度同壳对比与现场硬约束量距
1. **独立多方案管理面板（同壳 A/B/C 方案组）**：把同一实测铺位的多个摆法组织在一起，并支持把 A/B 方案对比表与双平面图直接打进同一份《合伙人方案书》。
2. **承重柱 / 排烟井 / 给排水立管按内墙角量距定位**：将 `surveyWall` 基准复用到现场硬约束构件，老板拿物业交房图即可毫米级落位。
3. **局部框选区域试排座**：在已有布局的某一块空白区拖框，只针对该区域试排卡座/散台并调净距。

### 第三阶段：3D 空间表现与施工交底升级
1. **窄铺 3D 外墙智能透视/面向相机隐藏**（借鉴 `blueprint3d` / `openPlan3D`），解决小面宽深进深铺位旋转观察时外墙挡视野的问题。
2. **分区快速飞入镜头**（借鉴 `wy51ai/floorplan-3d`）：点击后厨/水吧/客区标签，3D 镜头平滑飞入该区域审视。
3. **实测外墙与门窗距角复核交底表**：直接附在《合伙人方案书》末尾，方便交由装修队与房东复尺确认。
